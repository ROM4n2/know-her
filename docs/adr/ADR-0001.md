## Context

know-her 定位为依托 GitHub 开放协作的妇科与性健康科普知识库：外链+短摘要、透明可追溯、四段人工审核（来源核验→版权检查→医学准确性→敏感度）、静态站点无后端数据库、隐私优先。vault-grill 双镜评审（用户与产品体验层 + 技术与工程实现层）产出 24 条发现，Frontier 分 5 轮共 7 题全部由用户拍板，形成本 ADR。本项目无 Vault 目录结构，按 skill 规则 ADR 落 `docs/adr/`，不写入任何 Vault 路径。

## Decision Drivers（双镜）

- **用户体验与产品层**：需求真伪未验证（既有供给：丁香医生、默沙东中文、KnowSex、matters.love 等）；敏感题材的可发现性在主流渠道存在现实摩擦〔平台审查风险为假设〕；信任字段可伪造（仿冒站同样展示"专家审核"）；"个体化建议"无可判定定义导致审核尺度漂移；隐私敏感读者的纠错通道与"实名 GitHub"矛盾。
- **技术与工程实现层**：GitHub 原生评审语义（无序 approve / CODEOWNERS）与"四段串行审核"不兼容；fork PR 与 GITHUB_TOKEN 自动化链路存在静默断点；无数据库 ⇒ schema/约束必须整体迁移 CI；复审到期、断链检测属时间型查询，与静态构建快照矛盾；定时任务（含 GitHub 60 天无活动自动禁用 scheduled workflow）会静默死亡；bus factor=1 时四段审核整体冻结且前端不可见。

## Decision Outcome（D1–D7）

1. **D1 需求验证先行**：先产出 `VALIDATION.md`（1 个核心用户画像 + 10~20 个真实 query 映射今天的结果页 + 缺口声明）；验证不过则转"不建站/供稿既有渠道"。验证完成前不冻结结构设计。
2. **D2 信任机制化最小集**（全现成组件，自研≈0）：Astro content collections + Zod `.strict()`/`superRefine` 把 schema 与跨字段不变式做成 required CI check（缺字段/非法状态/译文过期 = 合并阻断）；`review_due` 为派生值、过期构建期自动撤徽章；四段门 = Environments `required reviewers`（绑 Team、Prevent self-review）+ `needs:` 链 + Rulesets（bypass 留空）+ CODEOWNERS 绑 Team + org 2FA；候选去重进滚动 issue（GitHub App token 驱动）；`lychee-action` 定时链检 + healthchecks.io 心跳。
3. **D3 分发一等公民**：RSS/Atom + 现成 newsletter（Buttondown 等）、既有中文性教育资源目录收录、Schema.org `MedicalWebPage`/fact-checked 标注、隐私友好聚合统计（Plausible / CF Analytics）作搜索词盲区代理；"不收集个人数据"与"聚合流量统计"分开承诺。
4. **D4 审核人"人不到位⇒范围收缩"**：先只发布来源核验+版权+敏感度三段可完成的内容；医学准确性席位未凑齐 2 名资质可外部核验的签字人前，内容如实标记"未获医学复审"降级呈现；招到人后批量补审摘标。
5. **D5 敏感内容边界结构化**：① 红旗清单结构化进 frontmatter（复用 WHO/ACOG/中华妇产科指南急症指征），CI 缺失拒绝合并；② 年龄提示分层：一次性全局偏好（localStorage）替代逐页弹窗；③ "个体化建议"可判定化：禁第二人称条件句，一律第三人称枚举（"哪些人适用/不适用由医生判断"）。
6. **D6 多语言"单语上线、多语留位"**：中文先上线；URL / frontmatter / `translation_of` 结构预留 i18n；译文机制预定义：`translation_of` 单向引用源条目、源更新 ⇒ 译文强制 stale、未复审译文醒目横幅，绝不与已审核内容视觉等价；第 N 语言等"验证通过 + 双语医学审核人就位"再开。
7. **D7 纠错双通道**：GitHub Issue/PR + 零个人信息通道（免账号表单 Tally/Formspark 转匿名化 Issue 或匿名邮件别名）；敏感题材提供"不留任何联系方式"的纯文本提交路径。

## Consequences

### 采纳组件清单（全现成）

静态框架 Astro content collections + Zod；搜索 Pagefind（构建期分片索引，多语言零配置〔面板推荐选型〕）；链检 lychee-action + `actions/cache`（PR 只查 diff、schedule 全量、create-issue-from-file）；心跳 healthchecks.io dead man's switch + `last_run` 时间戳文件校验 + workflow 失败邮件；发布 smoke check（部署后断言 build-id marker）+ 页面展示最后更新时间/构建 SHA + `workflow_dispatch` 回滚 runbook；分发 RSS + Buttondown 类 newsletter + 目录收录 + Schema.org 标注 + Plausible/CF Analytics；纠错 GitHub + Tally/Formspark 类免账号表单。

### 由面板 P1/P2 折叠的条款

- `review_status` 定义为 enum 状态机（draft → in_review → published → stale/expired），非法跃迁拒绝；expiry 不留手填位（`review_date` + `review_interval_months` 派生）。
- 审核对象与发布对象绑定：frontmatter 记 `source_url` + `source_snapshot_hash`（或 retrieval date）+ `reviewed_commit`；新 push 强制重走审核；同文件候选 PR 用 `concurrency: group` 串行化。
- fork PR 无 secrets 原则；`pull_request_target` 仅做 metadata 操作（打 label），绝不 checkout PR 代码；门禁 check 无 `paths:` 过滤、始终运行。
- 抓取礼貌性：per-host 限速（约 1 req/s）、遵从 robots.txt `Crawl-delay` 与 `429 Retry-After`、明示自有 UA（项目名+联系方式）；大体量抓取快照不进 git（Artifacts/独立归档仓），主仓只存 frontmatter + 摘要。
- 仓库保持 public（开放协作前提 + Actions 免费额度约束）〔假设，若转 private 需重估预算〕。

### 正面后果

信任从文案变为机器强制（CI 阻断 + 派生状态 + 自动降级）；过期/未复审内容不可能带"已审核"徽章在线；断链、cron 饿死、队列积压均有可观测信号；四段审核有真实鉴权语义（Team 绑定 + 环境门禁）。

### 负面后果 / 代价

组件与 CI 初装成本；D4/D6 使冷启动内容面与语言面收窄；D1 使实现时点后移；外部服务（newsletter/统计/表单）增多，需逐个核对隐私承诺一致性。

### 风险与开放参数（移交 /vault-plan）

- 需求可能被验证证伪——按 D1 转策展路线，此为设计内退出通道，不是失败。
- 平台可见性风险〔假设〕：分发渠道可能对敏感题材拦截/限流。
- 医学审核人招募时间不可控；未就位期间 D4 降级标记生效。
- 开放参数：`review_interval_months` 默认值（面板曾提 +12 个月、18 个月硬阈值自动归档）、抓取频率与来源清单、newsletter/统计最终选型、VALIDATION.md 的 query 清单。

### 验证闸门

`VALIDATION.md`（D1）是后续一切实现工作的前置闸门：未完成不冻结结构设计，验证不过走 D1 的退出路线。
